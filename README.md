# Antiyoy с друзьями

Неофициальная некоммерческая браузерная адаптация Antiyoy для Telegram Mini Apps. Приватные комнаты на **2–6 живых игроков**, поочерёдные ходы, редактор карт. Ботов, уровней и кампании нет.

## Запуск

Требуется **Node.js 24**. Сторонних npm-зависимостей нет.

```sh
npm start
```

Откройте `http://127.0.0.1:3000`. Создайте комнату и поделитесь ссылкой. Для проверки двух игроков на одном компьютере используйте разные браузерные профили или `127.0.0.1` и `localhost`: это независимые гостевые сеансы. Обычные вкладки одного домена используют одну личность.

```sh
npm test
npm run check
```

Редактор доступен без входа. Черновик хранится на устройстве. Сохранённые карты и партии находятся в SQLite (`data/antiyoy.sqlite`). При перезапуске сервера партии сохраняются. Секреты, база и исследовательские файлы исключены из Docker-образа.

## Реализовано

- Генерация связных карт с одинаковыми начальными провинциями; размеры 4/6/9, материк и проливы.
- Редактор: суша, вода, цвета, деревья, столицы, фермы, башни, четыре вида войск, стартовое золото; отмена и повтор изменений.
- Импорт/экспорт JSON, личная библиотека карт и список своих партий.
- Приватная комната, приглашение по ссылке/коду, готовность, передача роли создателя.
- Независимые казны, доход и содержание, найм и объединение войск, соседняя защита, фермы, деревья, голод, разделение и объединение провинций, сдача и победа.
- Сервер проверяет личность, очередь, доступность клетки, деньги и номер версии партии. Клиент не может прислать готовое изменённое поле.
- Обновления через SSE, переподключение, дополнительное чтение состояния после сворачивания. Повторная отправка старого хода отклоняется.
- Telegram: проверка HMAC `initData` на сервере, приглашения `startapp`, безопасные отступы, виброотклик, подтверждение закрытия.
- Экран партии по присланным скриншотам: казна и чистый доход сверху, четыре кнопки снизу, оригинальные спрайты Yiotro.
- Серверная отмена действий текущего хода с восстановлением денег и поля у всех участников.
- Сообщения над своей столицей на пять секунд и сдача в любой момент через меню.
- Сенсорное перемещение и масштаб карты, подсветка доступных ходов, журнал действий.

## Развёртывание на существующем сервере

1. Настройте DNS и HTTPS для домена игры.
2. Поместите проект на сервер. Создайте `.env` **на сервере**, не коммитьте его:

```dotenv
PUBLIC_URL=https://game.example.com
BOT_USERNAME=YourBot
BOT_TOKEN=значение_из_BotFather
# Для Main Mini App оставьте пустым:
TELEGRAM_APP_NAME=
```

3. Запустите:

```sh
docker compose up -d --build
```

4. Направьте существующий HTTPS reverse proxy на `127.0.0.1:3000`. Пример нужного блока есть в `deploy/nginx.conf.example`. Для SSE **отключите буферизацию**. Не заменяйте существующий виртуальный хост целиком.
5. Укажите HTTPS-адрес в **BotFather → Bot Settings → Configure Mini App → Main Mini App**. Можно также настроить Menu Button. Основное приглашение: `https://t.me/YourBot?startapp=room_КОД`.
6. Откройте приложение с двух аккаунтов Telegram и проверьте создание комнаты, приглашение, передачу хода и возвращение после закрытия.

`compose.yaml` закрывает гостевой вход, требует данные бота, публикует порт только на loopback и сохраняет базу в постоянном томе `game-data`. В production cookie использует Secure, HttpOnly, SameSite=None и Partitioned для Telegram Web. Для нативных клиентов работает обычная проверенная сессия. Заголовок Origin проверяется на изменяющих запросах.

Без Docker: задайте `NODE_ENV=production`, `ALLOW_GUESTS=false`, `PUBLIC_URL`, `BOT_TOKEN`, `BOT_USERNAME`, запустите `npm start` под вашим менеджером процессов. По умолчанию приложение слушает только `127.0.0.1`.

Сервер рассчитан на **один процесс** Node.js. Для нескольких экземпляров нужны общая БД и транспорт рассылки. Делайте резервные копии SQLite штатным SQLite backup, либо копируйте весь каталог данных при остановленном сервере. Не удаляйте том при обновлении.

## Что пока отличается от оригинала

**Это ещё не подтверждённая копия «один в один».** Числовые правила и основные механики сверены с опубликованным классическим набором Antiyoy (`RulesetGeneric`), а не Slay. Подробные источники и границы проверки перечислены в `docs/RESEARCH.md`.

Экран партии обновлён по пользовательским скриншотам, подключены оригинальные PNG-спрайты. Карта и её генератор реализованы отдельно. Точную сборку из скриншотов установить не удалось: правила сверены с двумя открытыми репозиториями и доступным экраном обучения. Обычная башня теперь не требует содержания. Подробное сравнение и поведение новых функций — в [`docs/UPDATE-2026-09-25.md`](docs/UPDATE-2026-09-25.md).

Нет дипломатии, тумана войны, транспорта, таймеров/автопропуска хода и отмены после передачи хода. Все игроки видят карту. При отключении участника игра ожидает его возвращения: бот его не заменяет.

Сеть и Telegram-авторизация проверены локальными интеграционными тестами. Проверку внутри настоящего Telegram и публикацию нельзя считать завершёнными до подключения реального бота и HTTPS-сервера.

## Развёртывание на Render

В репозитории есть готовый [`render.yaml`](render.yaml). Он создаёт Docker Web Service на одном экземпляре и подключает persistent disk `/app/data` для SQLite. Для диска нужен платный план Render; масштабирование выше одного экземпляра для этой SQLite-конфигурации не включайте.

1. Загрузите проект в GitHub или GitLab и в Render выберите **New → Blueprint**.
2. Выберите репозиторий. Render обнаружит `render.yaml`; подтвердите создание сервиса `antiyoy-friends`.
3. В форме секретов задайте `BOT_TOKEN` и `BOT_USERNAME` (без `@`). Для стандартного адреса `https://имя-сервиса.onrender.com` `PUBLIC_URL` можно не задавать: приложение использует адрес Render автоматически. При подключении собственного домена добавьте `PUBLIC_URL` с полным HTTPS-адресом домена.
4. После успешного деплоя проверьте `https://ваш-адрес/health`: ответ должен содержать `{"ok":true}`.
5. В BotFather укажите этот же HTTPS-адрес как Main Mini App. Приглашение в комнату имеет вид `https://t.me/YourBot?startapp=room_КОД`.

Render Blueprint намеренно использует `sync: false` для токена и имени бота: эти значения вводятся в панели Render и не сохраняются в Git. Persistent disk сохраняет партии и карты между перезапусками; резервную копию SQLite делайте перед изменениями сервиса.

## Структура

- `shared/engine.mjs` — чистый детерминированный движок и валидация карт.
- `server/index.mjs` — HTTP API, комнаты, SQLite, SSE, сессии.
- `server/auth.mjs` — криптографическая проверка Telegram.
- `public/app.mjs` — клиент, редактор, лобби, интеграция Mini App.
- `public/board.mjs`, `public/art.mjs`, `public/game-ui.mjs` и `public/game.css` — поле, оригинальные спрайты и игровой интерфейс.
- `server/undo.mjs` и `server/messages.mjs` — обратные изменения для отмены и пятисекундные сообщения.
- `tests/` — правила, подпись Telegram, настоящие сетевые запросы, SSE и перезапуск сервера.
